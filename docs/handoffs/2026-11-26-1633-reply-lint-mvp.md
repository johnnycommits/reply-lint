# Reply Lint MVP

2026-11-26 16:33 America/Chicago. Branch `cursor/reply-lint-mvp-68d1`.

## What was built

Advise-only Manifest V3 extension. A content script finds the reply composer, reads the draft, and renders a shadow-DOM panel beside it. Checks are pure functions over `signals/signals.json`. The service worker fetches that file once a day, validates it, and falls back to the copy bundled at build time. Pace counts and recent reply text stay in `chrome.storage.local`.

Checks: typed vs pasted, sounds-human phrases, engagement bait, hashtags, mentions, links, duplicate text, reply pace, invites-a-conversation, plus length and media as info only. Every row is tagged X's code, our heuristic, both, or no fixed rule. Weights and line citations are pinned to x-algorithm `52d45989090e63992ba04e4f6cfccd73bf8cc05c` and locked by a unit test.

Stack: TypeScript, Vite multi-entry (no CRXJS), Vitest, ESLint, Prettier. Load unpacked from `dist/`.

## How to load and test

```bash
npm install
npm test
npm run lint
npm run build
```

Chrome → `chrome://extensions` → Developer mode → Load unpacked → `dist/`. Branded Chrome 137+ ignores `--load-extension`; use the extensions page.

Fixture, no X login:

```bash
npm run demo
```

Open http://127.0.0.1:4173/composer.html with the extension loaded. Type, paste, toggle media, switch light/dark, click Reply. The page's own counter must increment. The draft text must stay as you left it.

Options: extension details → Extension options. Pace limits, check toggles, signals URL.

- `npm test`: 23 tests. Schema, weight table, each check's tag, invalid signals rejected, reply double-click counted once, fetch only in the service worker.
- `npm run lint` and `npm run build`.

  - Typing `What timeout did you hit?` goes to All clear.

  - A longer pasted draft also warned on paste, two hashtags, and a link, and left length and media as info.
  - Clicking Reply incremented the page's own counter and did not change the draft. The local pace count went from 0 to 1.
  - Options page shows 8/hour, 40/day, the default signals URL, and the nine toggles.

## Not verified

- A logged-in x.com or twitter.com session. The real composer DOM was not exercised. Selectors are isolated in `src/content/selectors.ts` because that DOM moves.
- A successful remote fetch. This repo is private, so raw GitHub returns 404. No token was added.
- The `chrome.alarms` daily fire. The alarm is created on install; only the fetch function's failure path was observed, via the footer.
- Duplicate-text against two real sent replies on X. The compare ran against storage written by the fixture's Reply click.

## Known limits

- Composer, reply button, and media selectors will break when X changes `data-testid`s. That is the first file to edit.
- Paste detection uses the paste event. If the browser gives no clipboard text, the row stays a warning until the box is cleared.
- Pace and duplicates only see replies clicked while this extension was installed, for 48 hours, capped at 100.
- Character count is plain characters, not `weighted_text_len`.
- The manifest matches `127.0.0.1:4173` and `localhost:4173` so the fixture works. Remove those before a store build if you do not want the extension on local pages.

## Open decisions

1. How the daily fetch should reach a private repo: make the file public, use a gist or GitHub Pages URL, or stay on the bundled copy. Do not embed a token. Hosts allowed today are raw GitHub, gists, and `*.github.io`.
2. Pace defaults are 8 per hour and 40 per day. They are guesses. X does not publish the `fast_reply_spam_post` threshold.
3. Phrase lists are a starting set and will be wrong until you edit them.
4. The link warning fires on any link. It is a heuristic and it is noisy if you reply with links on purpose. The options page can turn it off.
5. Whether the fixture host matches stay in the manifest.
